# 交接包⑦：M5 · 3b 顺序对比正则首组（云端，Cursor 执行）

代号：**M5-3b-order** ｜ 产出：2026-09-01 ｜ 承接：Cursor → 云端 GPU

## 1. 目的与里程碑

**M5：正则首组「训练+测试+复诊断」闭环**。在 B0 协议上只加 `L = L_CE + λ·L_order`
（margin 版，手册 §3.1），训练两个 λ（1 / 5，首组 2 点网格看 λ→OS 趋势），
各自 10000 ep 测试 + 复跑 3a 诊断。验收三件套（§3.3）：① Acc 相对 B0 变化（±CI）；
② **OS 应上升**（模型变得更会用顺序的直接证据）；③ 分支 Acc。

L_order 用 **O-1 免费午餐**（enh 正序编码一次、5 个负排列按 K 轴 index_select，
零额外文本前向，单测已验 reindex≡重编码）。3b 从零训练（非加载 B0），seed 916，
与 B0 参照实例（56.92）**配对可比**。

- 环境/数据/CLIP：同 B0（torch 2.2.2、`data/full/` 已抽帧、`CLIP_VIT_B16_PATH` 已设）。**训练型，显存同 B0 ~14.7GB，需 24GB 卡。**

## 3. 执行步骤

### 3.0 smoke（必做，发全量前）
先用 mini 验证 L_order 训练图通路（手册 §8）：
```bash
# 复制 config_mini.yaml 为 config_mini_3b.yaml，加 order_lambda: 1.0 / order_margin: 0.1
TA_CONFIG=config_mini_3b.yaml python run.py
```
通过判据：端到端无报错；控制台每 epoch 打印 `L_order <值> (lam=1, lam*Lo=<值>)`；loss/L_order 有限、无 NaN/Inf；checkpoint 保存。

### 3.1 每个 λ（1、5）闭环
```bash
# (a) 训练+终测（10 epoch × 1000 ep + 终测 10000 ep），约 3.7h
TA_CONFIG=config_3b_lam1.yaml python run.py 2>&1 | tee 3b_lam1_console.log
# (b) 复诊断：复制 config_3a_final.yaml → config_3a_3b_lam1.yaml，把 checkpoint 改为
#     (a) 存下的 best <acc>.tar（workspace_3b_lam1/.../），跑 diagnose.py，约 3.7h
TA_CONFIG=config_3a_3b_lam1.yaml python diagnose.py 2>&1 | tee 3b_lam1_diag.log
```
λ=5 同上（config_3b_lam5.yaml → 复诊断）。可串行。

- 监控（手册 §3.1）：训练日志的 `L_order` 量级与 `lam*Lo` 占比；Acc 曲线是否被压制。
- 断点续跑：改对应 config 三字段（load_weights/checkpoint/start_epoch）。

## 4. 成功判据

- [ ] smoke 通过（L_order 有限、无 NaN、checkpoint 存）；
- [ ] 两个 λ 各自训练 10 epoch 完成、终测 10000 ep 出数；
- [ ] 两个 λ 各自复诊断出 OS（sanity 仍 true）；
- [ ] 台账三件套齐全：Acc(λ) vs B0=56.92、OS(λ) vs B0=0.21、分支 Acc。

## 5. 判读（Claude 收包后，手册 §3.3）

- **OS 单调随 λ 上升** + Acc 不显著下降 → 3b 有效（模型变得会用顺序），进 M6 消融表补更多 λ；
- OS 不动或 Acc 明显下降（L_order 压制 L_CE）→ 调小 λ / γ 或换 InfoNCE，记录；
- 结合 3a 基线（OS=0.21±0.13）判断 ΔOS 的显著性（配对 CI）。
