## 3. 云端准备步骤（含环境四坑自查）

1. 实例：单卡 **24GB 显存起步（3090 / 4090 24G）**。fp32 单 episode 前向+反向真实峰值 **~14GB**（`torch.cuda.max_memory_allocated` 实测 13.9GB / reserved 14.3GB，与卡无关；本地 8GB 卡是靠 WDDM 溢出到系统内存才跑起来的，因而很慢）。**24GB 是舒适下限（约 10GB 余量、不溢出）；显存维度与数据集规模无关，smoke/试水/B0 同为 ~14GB。48GB 无必要。** 多卡实例可用 `num_gpus>1` 走 DataParallel 缩墙钟，非必需。
2. 环境：Python 3.9＋`pip install -r requirements.txt`。四坑自查：
   - [ ] **坑 A**：CLIP 用 `pip install git+https://github.com/openai/CLIP.git`（**禁止** `pip install clip`，PyPI 同名包是别的东西）；
   - [ ] **坑 B**：`export CLIP_VIT_B16_PATH=/path/to/ViT-B-16.pt`（代码已改为环境变量优先，仓库相对 `../dataset/checkpoints/` 兜底）；
   - [ ] **坑 C**：本包使用 `config_b0.yaml`，`method: taskadapter` 已填，无需动 `config.yaml`；
   - [ ] **坑 D**：`config_b0.yaml` 的 `num_workers: 8`，按实例核数可上调至 16。
3. 数据展开（仓库根目录执行；解包 webm 到任意目录，下称 `$VID`）：
   ```bash
   export PYTHONPATH=$(pwd)
   # 全量训练划分：64 类 × 100 段 = 6400
   python scripts/make_mini_subset.py --annotations ssv2s_annotations/train.txt \
     --video-root $VID --output data/full --classes 64 --clips 100 --seed 916 --splits-out train.txt
   # 全量测试划分：24 类 × 100 段 = 2400（somethingcmn 的 val 与 test 同文件）
   python scripts/make_mini_subset.py --annotations ssv2s_annotations/test.txt \
     --video-root $VID --output data/full --classes 24 --clips 100 --seed 916 --splits-out val.txt,test.txt
   ```
   预计 40–80 分钟、磁盘约 16GB（8800 段全帧 JPEG）。抽帧脚本具备断点跳过（已抽完的段自动跳过）。
4. 数据体检（手册 §1.2 三项）：`wc -l data/full/smsm_cmn/annotations/*.txt`（应为 6400/2400/2400）；每类计数 `awk '{print $3}' ... | sort | uniq -c`（应各 100）；随机开 3 个帧目录目检帧序。

## 5. 预计资源（首跑，待实测校准）

| 项 | 估计 | 依据 |
|---|---|---|
| 显存峰值 | **~14 GB**（fp32，batch=80 帧，含反向） | `max_memory_allocated` 实测 13.9GB；需 24GB 卡 |
| 训练墙钟 | 待试跑实测（**本地 30s/ep 不可用作折算**——那是 8GB 溢出到系统内存的拖慢值；24GB 卡无溢出，实际会显著更快） | — |
| 终测墙钟 | 待试跑实测（10000 ep，无反传更快） | — |
| 费用 | 全程约 ¥40–70（3090 ~¥1–1.3/h、4090 ~¥2–3/h；试跑测出单 ep 秒数后精算） | 待实测 |

> ⚠️ 墙钟估算重置：此前基于本地 30s/ep 的折算作废——本地是 8GB 卡 WDDM 溢出的拖慢值。24GB 卡不溢出，单 ep 会快得多。**必须用 §4 小规模试跑实测单 ep 秒数,再乘 10000+10000 精算全程与费用。**

墙钟若不可接受：多卡 DataParallel（`num_gpus` 上调）或换更强单卡，协议不变。

## 6. 成功判据（逐项勾选）

- [ ] 小规模试跑端到端无报错，loss 有限；
- [ ] 全量训练 10 epoch 完成：loss 全程有限无 NaN/Inf、整体下降；epoch 9 验证触发 best checkpoint 保存；
- [ ] 终测 10000 episode 完整出数（每 1000 打印滚动均值±CI）；
- [ ] **定标判据**：终测 Acc 与 63.6 差距 ≤ 1.0 个百分点 → B0 通过；
- [ ] 若差距 > 1.0pt：**不调参**，按手册风险清单顺序排查（① 数据：划分/抽帧/帧数字段/采样协议 → ② CLIP 权重来源与 fp16 路径 → ③ 超参），排查记录随 returns 带回（P2 修复本身可致基线相对 63.6 移动，差距方向与幅度需在报告中解释）。
