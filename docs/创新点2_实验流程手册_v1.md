# 创新点 2 · 实验流程手册 v1
（阶段 A 语料生成 → 阶段 B 基类质检 → 阶段 C 训练侧集成与 episode 择优 → 阶段 D 实验矩阵 → 阶段 E 分析与素材；里程碑 M10–M11）

**依据**：《后续创新点方案设计 v1》§二（三件套职责重划、协议红线、变长 K 工程）；仓库事实沿用《创新点 3 手册》实读结论。
**前置条件**：创新点 1 的 `ot_align.py` 可用（阶段 B 质检与 2c 择优复用其 OT 拟合代价；若尚无最优 ε/λ/ρ，先以平衡 OT λ=0 作临时参数，后续换用主线值重算一次）；退化的均匀窗口代价实现（用于解耦消融）。
**已拍板决策**：语料主线 **GPT-4**；**Qwen2-7B-Instruct、Llama-3-8B-Instruct** 作鲁棒性消融（同提示、同温度、同种子，整套流程各跑一遍）；**2c 在训练期启用**（训练/测试一致），墙钟超标再退测试期 only。

**协议红线（贯穿全手册）**：测试类（24 类）的视频**在任何离线步骤中都不得用于过滤或评分其语料**；测试类的自适应只来自每个 episode 的支持集（2c）。基类（64 类）视频用于质检，验证类（12 类）用于阈值/配方选择。

---

## 一、阶段 A：语料生成（离线，可在阶段 0 期间并行；M10-a）

### 1.1 生成规格

- 对全部 100 类 × K∈{2,3,4,5} × n=3 次采样（温度起始 0.7，记录实际值）→ 每类至多 12 个候选。
- **提示模板（prompt_v1，英文，版本化保存）**，起始版本如下，允许微调但每次改动升版本号：

```
You are annotating a video action recognition dataset (Something-Something v2).
Action label: "{label}"
Decompose this action into exactly {K} sequential sub-actions as they would appear
in a short video clip.
Rules: (1) strictly chronological; (2) each sub-action is ONE sentence describing
what is VISIBLE (hands, object, motion, camera view); (3) no intentions, feelings or
reasons; (4) keep objects generic exactly as in the label ("something" stays
"something"); (5) output JSON only: {"sub_actions": ["...", "..."]}
```

- 拼接入模型时沿用现有模板 `A video of action about {类名}: {子句}`（models.py L92），保证与 B0 可比。
- **三个来源分别生成**：GPT-4（API，记录返回的模型版本串）；Qwen2-7B-Instruct 与 Llama-3-8B-Instruct（本地推理，fp16 在 24GB 单卡可承载，或走 API 提供商——二者择一并记录；不同推理框架的采样不可完全复现，故**原始输出全部落盘**）。
- 去重：标准化文本（小写、去标点、折叠空白）后精确去重。

### 1.2 Schema 与文件

- 新文件 `corpus/classes_somethingcmn_v2_{source}.json`，`source ∈ {gpt4, qwen2_7b, llama3_8b}`：

```
{ "<类名键（与 utils.smsm_c 一致）>": {
    "label": "...",
    "candidates": [
      {"cand_id": "v1", "K": 3, "subs": [...], "source": "v1", "note": "原语料"},
      {"cand_id": "g-K2-s0", "K": 2, "subs": [...], "source": "gpt4",
       "gen_seed": 0, "temperature": 0.7, "prompt_version": "v1"},
      ...
    ]}}
```

- **原 v1 三段语料作为候选 `v1` 保留在每类候选集中**（保证 2c 至少可回退到基线语料）。
- 随仓库入库：生成脚本、提示词文件、请求/响应原始日志、种子；`utils.read_yml` 增加 v2 读取分支，v1 YAML 原样保留。

### 1.3 文本侧过滤（全类适用，不看视频）

- 长度界（每句词数上下限，起始 6–25 词）；句内出现意图/心理类动词（want/try/intend/decide 等，维护一份词表）剔除该候选；
- 候选内冗余：K 句两两 CLIP 文本余弦，最大值超过阈值（起始 0.95，在基类分布上校准）剔除；
- 候选间近重复：跨候选整体文本余弦超过阈值合并；
- 输出过滤日志（每类保留数、剔除原因统计）。

## 二、阶段 B：基类质检（M10-b）

### 2.1 视频侧特征缓存

- 基类 64 类，每类采样至多 N 个训练视频（起始 30，按类视频数封顶）；评测变换（Resize+CenterCrop）、中心均匀采 8 帧；**冻结 CLIP ViT-B/16（不含任何 adapter）**抽帧特征，L2 归一化后缓存到 `qc_feats/{class}.pt`。
- 用冻结 CLIP 而非 B0 的理由：质检不依赖任何训练产物，语料可先于模型定稿；缓存一次多来源复用。

### 2.2 候选拟合分

- 对类 c 的每个候选 v：用 `ot_align.ot_stage_scores` 计算每个视频的 S（8×K_v，`frame_source: raw` 口径，无 ca），类内取均值 → `fit(c,v)`；同时记录 π 的阶段质量分布（用于识别"某阶段从不被分到帧"的幻觉候选）。
- **保留规则**：按 `fit` 排序，每类保留 top-2 生成候选 + `v1`（共 ≤3）；`cand_topk` 作为可调项（消融用）。
- **验证类用途**：12 个验证类的视频侧质检**允许**做，用来校准 §1.3 的阈值与 `cand_topk`（看过滤后下游验证精度或 fit 分布），不进入任何训练类别的语料决策以外的用途。
- **测试类**：只做 §1.3 文本侧过滤，候选全部保留给 2c。
- 输出：`classes_somethingcmn_v2_{source}_qc.json`（带 fit 分与保留标记）+ 质检报告（每类保留数、fit 分布直方图、阶段质量分布异常清单）。

### 2.3 全局 K 行的候选确定（供阶段 D 的 K 扫描使用）

- 基类：取该 K 下 fit 最高者；测试类（无视频可用）：取该 K 下**文本侧冗余度最低**者（确定性、协议干净）。写入 `forcedK_{k}` 索引字段。

## 三、阶段 C：训练侧集成与 episode 择优（M11）

### 3.1 语料装载与变长 K

- `models.py` L86–101：按候选构建提示；`self.text` 本就逐类调用（L98–99），每类 K 可不同；L101 的 `torch.stack` 改为逐类列表（或 pad 到 K_max 并在 OT 中屏蔽 pad 列——推荐列表法，避免 pad 干扰 b 边际）。
- 创新点 1 的 `ot_stage_scores` 按类分别调用（K_c 变长），结果拼回 (N_Q, n_way)。

### 3.2 2c 择优规则

- 支持视频经 ca 得对齐帧（与查询路径一致，Option A；ca 无参数，额外前向便宜；支持批内的跨视频混合与查询侧同性质，如实记录）。
- 对 episode 内每类 c 的每个存活候选 v：`cost(c,v)` = 支持对齐帧与候选阶段文本的 OT 传输代价（主线 ε/λ/ρ）；选 `argmin`；平局取 K 小者。
- 选择是离散路由，**不反传**；梯度只流经被选候选。
- **训练稳定性开关** `sel_warmup_epochs`：前若干 epoch 固定用 `v1`，之后启用择优（起始值 2，视训练曲线调整）。
- **测试期缓存**：adapter 冻结后，一次性预计算 100 类全部候选的阶段特征，择优退化为纯算术。
- 每个 episode 记录被选 `cand_id` 与 K（CSV），供阶段 E 画像。

### 3.3 配置键

`corpus_version: v1|v2`、`corpus_source: gpt4|qwen2_7b|llama3_8b`、`cand_topk`、`sel_mode: off|test|train_test`、`sel_cost: ot|uniform_window`（解耦消融）、`sel_tiebreak: smallK`、`sel_warmup_epochs`、`forced_K: null|2|3|4|5`。

### 3.4 单元测试

| 编号 | 内容 | 通过标准 |
|---|---|---|
| U5 | 同一 episode 内 K∈{2,3,4,5} 混合 | 前向/反向不报错，S 形状 (N_Q, n_way) |
| U6 | 择优确定性 | 同一特征输入重复择优结果一致；平局规则生效 |
| U7 | 回归 | `sel_mode: off` + `forced_K: 3` + `corpus_version: v1` 与创新点 1 主线逐元素一致 |
| U8 | 缓存一致性 | 测试期缓存特征与即时前向一致（容差内） |

## 四、阶段 D：实验矩阵（M11）

## 五、阶段 E：分析与论文素材

- **选择画像**：被选 K 的分布（训练期 vs 测试期）；K 与类均帧数（annotation 第二列现成可得）的相关；对 24 个测试类做一次人工标记（pretend 类 / 多阶段类 / 单一运动类），看被选 K 的差异——回应"提示工程"质疑的核心分析。
- **来源一致性**：三来源在同一类上被选 K 的一致率、候选文本的跨来源相似度；精度差异与一致率并列报告。
- **择优稳定性**：同一测试类在不同 episode 中被选候选的熵；熵高的类单独列出并解释。
- **定性样例**：3 个类的候选清单 + fit 分 + 被选结果 + π 热图。
- 发布物：三来源语料 JSON、提示词、种子、质检报告。

## 七、风险与应对

- **候选差异过小、择优无信号**（画像中被选分布接近均匀、fit 分方差小）：提高温度或换提示版本重新生成，升版本号重跑阶段 A/B。
- **训练期择优导致早期震荡**：增大 `sel_warmup_epochs`；仍不稳则退 `sel_mode: test` 并如实报告。
- **1-shot 择优方差大**：以 §五的稳定性统计如实呈现；平局规则与 `v1` 回退保证下限。
- **开源模型生成质量差**：这本身是鲁棒性消融的结论之一，不做人工修补；只保证流程一致。
- **墙钟**：训练期择优的额外文本前向按 `cand_topk`≤3 控制；首个 epoch 实测后决定是否退测试期 only。
