## 一、创新点 1 详案：语义条件、顺序保持的软阶段分配（不平衡 OT 重写式(16)）

### 1.1 数学定义

对每个（查询 q，类 c）对求解一个 7×K 的小规模传输问题（K=3 起步；变长 K 见创新点 2）：

- **输入**：查询对齐帧特征 F̄ = [f̄₁..f̄₇] ∈ R^{7×d}（现取自 `q_aft_tm`，L2 归一化）；类 c 的阶段文本特征 T_c = [t₁..t_K] ∈ R^{K×d}（`enh_embedding`，L2 归一化）。
- **代价**：C(i,s) = 1 − f̄ᵢ·tₛ（**fp32 计算**，见 §1.3）。
- **顺序先验**：位置偏差矩阵 D(i,s) = ( (i−1)/6 − (s−1)/(K−1) )²，惩罚代价 C̃ = C + λ·D。λ=0 即纯内容驱动；λ→大退化为近似固定带状分配。（这是 OPW 式带状先验的最简可实现形式：等价于对以近对角先验为参照的 KL 正则。）
- **边际**：帧侧 a = 1/7·**1**（硬约束——每帧的质量必须去某个阶段）；阶段侧 b = 1/K·**1**，以强度 ρ 的 KL **软约束**（单侧不平衡：允许某阶段近零质量，对应掐头去尾片段）。
- **目标**：min_{π≥0} ⟨π, C̃⟩ + ε·KL(π‖a⊗b)，s.t. π**1**=a（硬），ρ·KL(πᵀ**1**‖b)（软）。
- **求解**：log 域 Sinkhorn，阶段侧对偶更新乘阻尼 τ = ρ/(ρ+ε)；固定迭代数（建议 30 起步，记录收敛残差）；对迭代展开做自动微分（7×K 规模，反传开销可忽略）。
- **输出与打分**：阶段质量 mₛ = Σᵢ π(i,s)；阶段视觉特征 f̂ₛ = normalize(Σᵢ π(i,s)·f̄ᵢ / max(mₛ, δ))；语义分 S(q,c) = Σₛ ŵₛ·cos(tₛ, f̂ₛ)，其中 ŵₛ = mₛ/Σₛ′mₛ′（质量加权；等权版作消融）。S 直接替换式(16) 的 cos_score，输出形状即 P2 修复后的 (N_Q, n_way)，式(17) 融合与损失完全不动。
- **消融链五档**（对应逐步打开的开关）：固定窗口(B0) → 平衡 OT（ρ→∞, λ=0）→ +顺序先验（λ>0）→ +不平衡（ρ 有限）→ soft-DTW 变体（严格单调路径的替代公式化，作为伸展项，实现较重、排最后）。

### 1.2 关键理论性质（新，直接写进论文）

**命题：当 λ=0 且 b 均匀时，S(q,c) 对子动作顺序的任意排列严格不变。** 理由：对阶段做列排列 σ 后，代价矩阵按列同排（C′(i,s)=C(i,σ(s))），可行域与正则在列排列下对称（a 固定、b 均匀、KL 对称），熵正则解唯一 ⇒ π′(i,s)=π(i,σ(s))，于是 f̂′ₛ=f̂_{σ(s)}、m′ₛ=m_{σ(s)}，求和后 S 不变。**顺序信息完全且仅由 λ>0 的先验注入。**

三个直接后果：

1. **与创新点 3 的诊断闭环**：结合手册中的 O-1（O-MSA 对子动作轴排列等变，待单元测试证实），可以给出一张"预测→验证"表——固定窗口（刚性顺序耦合，OS 取决于特征阶段特异性）／OT λ=0（**OS≡0，构造性保证**）／OT λ>0（OS 随 λ 可调）。诊断协议（3a）由此从"测一个数"升级为"测量模型在'内容驱动↔顺序驱动'轴上的位置"，1 与 3 拼成统一叙事。
2. **与 3b 正则的兼容性约束**：λ=0 时 s(正序)≡s(乱序)，margin/InfoNCE 的梯度恒为零——**顺序对比正则只有在固定窗口或 λ>0 的 OT 上才有信号**。组合实验必须在 λ>0 配置上做，消融表要写明这条依赖。
3. **叙事升级**：固定窗口＝内容无关的极端顺序先验；纯 OT＝顺序无关的极端内容驱动；λ 在两极间插值。"−1.7 异常"（Table 4：对齐单独用 58.5 vs 基线 60.2【原文】）的机制解释与修复路径都落在这根轴上。

### 1.3 代码集成（基于实读）

- **替换点**：`models.py` L102–106（`cos_score` 的三窗口循环与 `/9`）。`q_aft_tm`（[7, N_Q, d]）与 `enh_embedding`（[K, n_way, d]，L101 stack+permute 产物）为输入。
- **批处理伪代码**（einsum 索引按此意图实现，以跑通的单测为准）：

```python
F = l2norm(q_aft_tm.float().permute(1,0,2))          # [NQ,7,d]  fp32 岛
T = l2norm(enh_embedding.float().permute(1,0,2))     # [C,K,d]
Cmat = 1 - torch.einsum('qid,ckd->qcik', F, T)       # [NQ,C,7,K]
Ct   = Cmat + lam * Dmat[None,None]                  # Dmat: [7,K] 预先构建
pi   = sinkhorn_log(Ct, a, b, eps, rho, iters=30)    # 批量 (NQ,C) 个 7xK 问题
m    = pi.sum(dim=2)                                 # [NQ,C,K]
fhat = l2norm(torch.einsum('qcik,qid->qckd', pi, F) / m[...,None].clamp_min(1e-6))
S    = ((m / m.sum(-1,keepdim=True)) *
        torch.einsum('ckd,qckd->qck', T, fhat)).sum(-1)   # [NQ, C]
sem_dists = S.half()                                 # 回 fp16，接式(17)
```

- **fp32 岛**：仓库两分支相似度均在 fp16（`utils.py:28`）；Sinkhorn 在 fp16 下不安全——OT 块内全程 fp32，出口再转半精度。
- **梯度通路**：t（文本 adapter，text_depth=2）与 f̄（视觉 adapter＋ca 路径）均在 C 与终分中出现，端到端可微；Sinkhorn 迭代展开反传。
- **朝向**：输出天然 (N_Q, n_way)，与 P2 修复后的视觉分支一致；保留形状断言。

### 1.4 设计决策清单（附推荐）

**一处对原创新点文档的修正**：原文档预期"对齐模块替换为非参数运算后参数量不增反减"。实读发现 CrossAttention 的 `to_out` 恒为 Identity（heads=1 且 dim_head=dim ⇒ project_out=False），somethingcmn 下 `ln_1` 也是 Identity——**基线的对齐模块本来就近乎零参数**。故"更少参数"卖点不成立，论文表述改为"**零新增参数（或仅 2–3 个可学标量）**的公式化替换"。

### 1.5 调参路线（坐标式三步，避免三维联合网格）

1. **步 A**：平衡 OT（λ=0, ρ→∞），只扫 ε（起始量级建议围绕代价尺度 C∈[0,2] 取对数网格，如 0.01/0.05/0.1/0.5，以实验为准）。由 §1.2，此档 OS≡0，同时给出"纯内容驱动"的精度基线。

   每步开发规模 600–2500 episode 复用 3a 的配对诊断脚本；进终表的配置才跑 10000。

### 1.6 实验计划

- **主表**：消融链五档 × {Acc±CI, OS}，SSv2-Small 5w1s，均对照 B0、配对 episode。
- **异常修复叙事**：注意 Table 4 的"对齐单独使用"行（58.5）没有子动作、无法被 OT 直接复刻（OT 天然需要阶段文本——这正是"语义条件化"论点本身）。论文中该表重构为：{B0 固定窗口, +OT(λ=0), +OT(λ>0), +OT(λ>0,ρ)} 的组件表，异常行用作机制解释的靶子而非复跑对象。

### 1.7 单元测试与里程碑

- **U1 排列不变性测试**：λ=0 配置下，对阶段文本做任意排列，断言 S 逐元素不变（数值容差）——同时验证实现正确性与 §1.2 命题。
- **U2 极限退化测试**：λ 取大、ε 取小、平衡边际时，π 应近似集中在带状对角（与固定窗口可比对的形态）。
- **U3 梯度健康**：一个 episode 上 backward 无 NaN/Inf，fp32 岛边界检查。
- **M7**：U1–U3 通过 + 步 A（平衡 OT）首训出数；**M8**：步 B/C 消融链完成（开发规模）＋ λ-OS/λ-Acc 曲线；**M9**：终表（10000）＋ 鲁棒性协议 ＋ π 可视化定稿。

### 1.8 风险

ε 过大退化为均匀分配（U2 形态监控）；ρ 与 λ 存在交互（坐标式扫完后对最优点邻域做一次 2×2 微网格复核）；OT 档若全面不敌固定窗口——λ 大端应能逼近固定窗口性能，若逼近不了优先怀疑实现而非思路（U2 是哨兵）。

## 二、创新点 2 详案：复杂度自适应分解＋语料质检＋episode 择优

### 2.1 三件套职责重划（关键协议修正，防数据泄露）

原文档未明确"质检用谁的视频"。**协议红线：测试类（24 类）与其视频绝不可用于离线过滤自身语料**——否则等于用测试数据校准模型输入。重划如下：

- **(a) 生成**：对全部 100 类生成多候选（见 §2.2），不看任何视频。
- **(b) 质检**：只用**基类（64 训练类）视频**打分过滤基类语料，并以**验证类（12 类）**做"生成配方"级选择（提示风格/温度/候选数等配方在验证集上比性能——这是标准验证用法）；测试类语料只做**纯文本侧过滤**（§2.3），不接触其视频。
- **(c) episode 择优**：新类（含测试类）的自适应完全靠**每个 episode 的支持集**在线择优——协议干净（支持集本来就是可用信息），这也是"任务条件化"叙事的落点。

由此，"类级自适应粒度 K"在测试类上的实现方式是：候选覆盖 K∈{2..5}，**由 2c 的支持集择优隐式选出 K**，而非离线钦定。

### 2.2 生成管线（离线，可在阶段 0 期间提前启动）

- 对每类、每个 K∈{2,3,4,5}：温度>0 自洽采样 n=3 次 → 去重（归一化文本）→ 每类至多约 12 个候选。提示中约束：有序、可视觉落地（禁意图/心理描述）、句式与现有语料同风格；沿用 `A video of action about {类名}: {子句}` 模板保证与基线可比。
- 产物：`corpus/classes_somethingcmn_v2.json`（新 schema：每类 `candidates: [{K, subs[], gen_id}]`），生成脚本、提示词、温度、种子全部入库随论文公开；`utils.read_yml` 加一个 v2 读取分支，v1 YAML 原样保留作对照。
- LLM 选型不设限（任意可 API 调用的强模型即可），成本一次性且极低。

### 2.3 质检打分

- **文本侧过滤（全类适用）**：长度界、去重、禁用词（意图类动词）、K 内句子间的冗余度（两两文本相似度过高者剔除）。
- **视频侧打分（仅基类＋验证配方）**：每类采样 M 个训练视频，冻结 CLIP 抽帧特征，候选的拟合分 = 创新点 1 的 OT 对齐代价（**直接复用 §1 的实现**——两个创新点共享一套对齐机器，是工程与叙事的双重协同）；按类保留 top-1/top-2 候选。质检开/关是消融开关之一。

### 2.4 变长 K 的工程

- 文本编码天然支持变长：`self.text` 本就逐类调用（models.py L98–99），每类 K 不同无需 padding；仅 L101 的 `torch.stack` 需改为逐类列表处理。
- 匹配侧：OT 的 7×K_c 天然变长（**2 依赖 1 的主因**）；若 1 不在场的退化方案＝均匀窗口（每阶段 ⌈7/K⌉ 帧）——保留此退化实现用于"择优本身有效"的解耦消融（优先级评估已要求）。

### 2.5 episode 择优（2c）

- 规则：episode 内每类 c，对其存活候选 v 计算**支持集拟合代价**（支持视频过 ca 得对齐帧——ca 无参数、额外前向便宜——与候选阶段做 OT，取传输代价），选 argmin；1-shot 下即单支持视频定夺，平局按 K 小者优先（奥卡姆）。
- **训练/测试一致性**：推荐**训练期同样启用择优**（评分规则免训练，逻辑一致）；成本 = 每 episode 文本前向 ×（候选数），若墙钟不可接受再退"测试期 only"变体并如实报告差异。测试期 adapter 冻结 ⇒ 全部候选阶段特征**一次性预计算**，择优只剩算术。
- 记录每个 episode 的被选候选与 K —— §2.6 画像的原始数据。

### 2.6 实验计划

- 全局 K=2/3/4/5 扫描 vs 类级自适应（主对比）；质检开/关；2c 开/关（含固定窗口退化版择优的解耦行）；语料 v1 vs v2。
- **选择画像**：被选 K 的分布、与类均视频时长（annotation 的帧数字段现成可得）及 pretend 类/多阶段类标记的相关统计——回应"提示工程"质疑的分析性证据。
- **语料迁移实验**（LGA 已示范此写法）：把 v2 语料喂给固定窗口的 B0（不带 OT），验证语料收益的通用性。
- 方差控制：语料版本固定种子；同一配置至少两个训练种子复跑一次以估计语料引入的方差（进论文的主配置）。

### 2.7 里程碑与风险

**M10**（可提前至阶段 0 并行）：v2 语料生成＋文本过滤＋基类质检完成；**M11**：训练侧集成＋消融表。风险：候选间差异过小导致择优无信号（画像会暴露，届时增大温度/候选多样性）；1-shot 择优方差大（平局规则＋报告择优稳定性统计）。

## 三、创新点 4a 设计（＋4b 的 go/no-go 门槛）

### 3.1 α 参数化（附验收测试）

现融合是逐元素乘（run.py：`vis*sem`，损失 ×64）。余弦分可为负，直接幂加权无定义，故给两个候选参数化，**验收标准：α 取默认值时在开发 episode 上与 B0 预测严格一致或差异在 CI 内**：

- **形 P（推荐先试）**：各分支先按查询做 softmax 成类概率（各配温度），融合 ∝ p_vis^{2α}·p_sem^{2(1−α)}；α=0.5 时为概率积——与"相似度积"不严格等价，须用验收测试实证校准温度。
- **形 L（参照）**：logit 凸组合 2α·vis+(1−α)·2·sem——和式融合，与乘式基线本就不同，仅作参照行。
- **对比基线（必做）**：全局固定 α*（验证集上调出的每数据集常数——对应 LGA 手调融合权的做法）；KIP 式免训练硬门控（按双分支稳定性二选一）——这两条是前文新颖性核查点名的划界对象，必须进表。

### 3.2 K=1 的伪验证协议

- 每个支持视频生成若干增广视图充当伪查询（时间侧：重抽 `frame_id` 的随机偏移；空间侧：RandomCrop）。**注意：SSv2 禁用水平翻转**——存在方向敏感类（如 pulling something from right to left），翻转会污染伪标签。
- 关键成本性质：两分支分数矩阵对伪 episode 各算一次后，**α 网格扫描是纯算术、零额外前向**；每 episode 的开销只有增广视图的前向。
- 选择规则：伪精度最大化，平局取 margin 最大；伪验证无区分度（曲线平坦）时回退全局 α*——回退率作为报告指标。
